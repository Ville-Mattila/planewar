## A-64 (TA-46, orchestrator ruling A-48) `EntityId` generation is 11 bits: ratified

**Evidence.** TA-46 reproduced 49,152 failed store-and-read checks in 100,000 alloc/free cycles on one projectile slot with the 12-bit generation (bit 31 set from generation 2048 on; `PackedInt32Array` sign-extends). With the A-20 zero-tick quarantine a busy projectile slot reaches generation 2048 within minutes of play.

**Decision.** A-48 stands as written: generation bits 20-30, `GEN_MAX` 2047, wrap 2047 -> 1, bit 31 always 0; wire ids stay `u32`; `core/MODULE.md` C10 is the invariant. The alternatives A-48 listed (mask at every read site, sign-extended canonical form, `PackedInt64Array` id fields) were each weighed again and lose on the same grounds: a missed mask is a silent equality bug, a negative canonical id breaks every `decode_u32`, and 64-bit id arrays change the 03 s3.2 / s3.3 layouts. The cost (an id recurs after 2,047 frees instead of 4,095; worst projectile case 68 s against a ~35-tick life) is accepted. 01 ADR-06 and 04 I15 ("generation << 20") stay true. `core/MODULE.md` drops its "awaiting confirmation" line.

## A-67 (AI-05) `autopilots.json` `flight` block: eight new keys, two meanings changed

**Context.** `FlightGains.KEYS` (sim/steer, AI-05) requires sixteen `flight` keys; 05 s4.4 listed eight (`kp_path`, `ki_path`, `kp_roll`, `kp_yaw`, `bank_threshold_deg`, `kp_speed`, `ki_speed`, `brake_overspeed_mps`) plus `k_guidance`, which the controller does not read. AI-05's flight-path-vector law needs `integ_max_rad`, `integ_band_deg`, `lead_max_deg`, `kp_att`, `kp_bank`, `bank_max_deg`, `t_trim`, `kp_turn_thrust` (05 s5.2 had `t_trim` 0.5 and the +-0.5 integrator clamp in prose). `kp_path` is now the nose lead per radian of path error (05: pitch-rate gain) and `kp_yaw` a pointing gain (05: fine-heading gain).

**Decision.** (1) `autopilots.schema.json` `flight` gains the eight keys with 05 s4.4 bounds (`kp_*` in (0, 10]; angles in degrees [0, 90] / [0, 180]; `integ_max_rad` [0, 3.2]; `t_trim` [0, 1]); the sixteen `FlightGains.KEYS` are **required whenever a `flight` object is present** (the object itself stays optional; `k_guidance` stays optional). No shipped def carries a `flight` block (the canonical fixture has none; `godot/content/defs/autopilots.json` does not exist yet), so this is an append in effect. (2) 05 s4.4's `ap_dart` example and s5.2's law table are patched to the AI-05 semantics with the tuned values of `godot/test/sim/ai/ai05_params.json` (kp_path 4, ki_path 0.3, integ_max_rad 0.8, integ_band_deg 6, lead_max_deg 80, kp_att 6, kp_yaw 6, kp_roll 3, kp_bank 1, bank_threshold_deg 10, bank_max_deg 60, t_trim 0.5, kp_speed 0.05, ki_speed 0.005, kp_turn_thrust 2, brake_overspeed_mps 20) as the anchors S-FLIGHT-1's AI-06 harness tunes. (3) **AI-19** writes every `ap_*` block (acceptance appended), including `lift_max_frac` 0.6 and `lift_min_time_s` 0.5 (AI-07's open item).

## A-68 (AI-05) `damping_only` dives: the thrust-limited figure is the acceptance for the A/B variant

**Evidence.** Under `lift_model = damping_only` the level-flight AoA is 27-33 degrees (TA-30) and nose-down authority is gravity plus the same thrust the speed loop needs; gain sweeps plateaued at ~2.4 s and ~17 % overshoot for a 15 degree dive; every other step meets 2.0 s / 15 % under both models.

**Decision.** 05 s5.2's acceptance (<= 2.0 s, < 15 %) binds the default law `speed_scaled` (R0 B.1, S-FLIGHT-1 kept it). For `damping_only` the 15 degree dive is accepted at **<= 2.6 s with < 20 % overshoot**, exactly as `sim/steer/MODULE.md` FC3 records and `test_damping_only_dive_is_thrust_limited` pins; no per-model gain sets (a second tuning surface for a variant nobody ships). SC-09 / SC-10 under `damping_only` stay printed, not asserted. 05 s5.2 gains the sentence.

## A-69 (AI-05 -> 05 s5.3, AI-13) Terrain lift: drop-free clearance, added to the vertical speed

**Evidence.** `TerrainProbe` predicts the ballistic path (0.5 g t^2 = 48 m at 4 s under g = 6). Fed raw into `v_cmd` as 05 s5.3 words it, the lift climbs a level ship out of the 60 m deck band over flat ground, because the lift law of the sim holds altitude that the probe says will be lost. The AI-05 rig (`terrain_flight_rig.gd::_flown_lift`) removes the drop and adds the lift to the current radial speed; SC-09 / SC-10 pass with it.

**Decision (05 s5.3 erratum).** The probe keeps the ballistic path for **TTI and PULL_UP** (an unpowered path is the pessimistic truth an emergency needs). For the **lift term** the clearance of sample k is the drop-free value `c_k + 0.5 g t_k^2`, i.e. the path a ship holding its current vertical speed flies; `lift = max(0, h_req - c_k') / max(t_k, lift_min_time_s)`, capped at `lift_max_frac * u`, and the brain commands `v_cmd.radial = v_r + lift` (the current radial speed plus the lift), never `lift` added to an altitude-hold command. `TerrainProbe.probe` is unchanged (ST1-ST4 hold); the subtraction is the caller's, because `ProbeResult` carries `worst_t_s` and the brain knows `gravity`. Owner: **AI-13** (Dart brain; acceptance appended) and every brain that calls `probe` for lift.

## A-70 (AI-05 -> 05 s5.5, AI-09) Landing law L4 has a height floor

**Evidence.** The TA-30 spike law's TRANSITION phase has no minimum AGL; fast entries from 15-40 m AGL scrape the ground short of the pad (Dart fast set: 37 of 200 runs scrape, then land; the spike counted them as landings).

**Decision (05 s5.5 erratum).** In **L4 TRANSITION** the vertical command never lets AGL fall below `landing.hover_agl_m` (25): while `agl < hover_agl_m` the law commands `vz_cmd >= 0` and the thrust-vector tilt is limited so the vertical component holds the floor; the descent begins in L5. A scrape (C_TERRAIN contact) during L4-L6 is a **failed landing** in SC-04's count, never a landing. AI-09 implements it (acceptance appended; it is fixing this in parallel, the rule is what it must match); `Assist.auto_dock()` (AI-10) inherits it because it runs the same L4-L6.

## A-71 (AI-04) Events reach `AiDriver.on_event` through the hook; registration follows SPAWN / DEATH

**Context.** `SimAiHook.on_tick(tick, view, sink)` carries no events; `AiDriver.on_event(ev)` exists (HIT wakes, DEATH unregisters) but nothing calls it. `AiDriver.register(id, cls)` has no caller either: spawns happen in `CommandApplier` (sim), which cannot name `sim_ai`.

**Decision.** (1) Contract append, `[planned: TA-57]` in `sim/MODULE.md`: `func on_event(ev: SimEvent) -> void` on `SimAiHook` (base: no-op). `SimWorld.step()` forwards the **previous tick's drained events** to the hook at the start of step 3, before `on_tick`, in `SimEvents` order. The sim owns the event list and the hook call, so one forwarding site serves the offline host and `ServerSession` alike and the AI sees events in tick phase; a session-side forward would need two implementations and would run outside `step()` (05 s1.3 forbids AI outside the tick). Events are forwarded once; the step-12 drain for net is unchanged. (2) **Registration is event-driven inside `sim_ai`:** `AiDriver.on_event` registers an AI-driven entity on `SPAWN` (class from `SimView.def_id` through a def -> class table built from `ContentSet`) and unregisters on `DEATH` (as today); `register()` / `unregister()` stay public for tests and scenario rigs. A POSSESSED entity stays registered and is skipped (AI-04 invariant). Code: **TA-57** (sim, Sonnet, 0.5 d) and **AI-37** (sim_ai, Sonnet, 0.5 d). (3) Think / bot periods stay constructor arguments until AI-19 / the bot-profiles task land (`AiDriver` reads `autopilots.think_period_ticks` then; recorded in AI-19's acceptance).

## A-72 (TA-21) The save header carries the content hash

**Context.** TA-21's `SimSerialize` header is magic, `FORMAT`, raw size, SHA-256 of the raw body; the PR said "no hash exists in the sim lane". It does: `WorldDefs.content: ContentSet` carries `content_hash` (32 bytes, N1), so the sim can write it without a new dependency.

**Decision.** Contract append, `[planned: TA-58]`: the header gains `content_hash` (32 bytes) after the body hash; `SimSerialize.read` refuses a file whose hash differs from the loaded `ContentSet.content_hash` with a new `Status.CONTENT_MISMATCH` (appended after `NEWER_FORMAT`; ordinals frozen). This is a layout change, so `FORMAT` bumps (to 8, after PR #47's format 7, A-79; no migration, as the versioning policy already says). Saves stay same-build (ADR-03 / ADR-06); the hash check turns a silent desync after a def edit into a refusal with a reason. Code: **TA-58** (sim, Haiku, 0.25 d).

## A-73 (TA-38 review) Line caps in `sim`: the extraction rule

**Evidence.** `collision.gd` and `local_sim_view.gd` are at the D7 cap (400 lines); `sim_world.gd` is at 317 on `main` and 333 on PR #47, which kept it there by composing `Economy`, `Production` and `Construction` behind `EconomyHub` (`sim/world/`).

## A-74 (GD-36) Fire-pipeline interpretations ratified; 03 s3.3 erratum on `ttl`

**Decision.** Ratified as merged and as `sim/combat/MODULE.md` CB10-CB14 record: (1) **`ttl` always counts the lifetime** (`lifetime_s - ttl` is the arming age CB6 needs); the flak **burst tick rides in `ProjectileStore.target`** (a flak shell never has a lock target), set at spawn to the closest-approach tick to the ship nearest the boresight plus `fuse_delay_s`, clamped to [`arm_s`, lifetime - 1 tick]. 03 s3.3's "`ttl` = time to burst for timed fuses" and "burst when `ttl <= 0`" are errata and now read so. (2) `burst_interval_s` is **start-to-start** (02 s4.4 "5-round bursts every 1.2 s"; `gun_turret` 5 rounds every 36 ticks). (3) `lock_cone_deg` is the **full apex angle** (02 s4.1 "Lock cone"; 0 or 360 = any direction). (4) Ship rockets lock ships, ground units and structures; towers lock their `target_kinds`. (5) Muzzle = centre + `fwd * radius`; slugs, flak, rail and shells inherit the carrier velocity, rockets fly at `speed_mps` only, bombs leave at carrier velocity + `eject_down_mps` toward the centre (02 s4.2 motion rule); the siege gun fires along `fwd` and the lofted solve is the Crawler brain's (AI-18). (6) Combat row p95 1.98 ms vs 1.2 on a heavy bench is recorded in 03 s4.2 row 9 notes for S-SIM-1 (A-62: no row moves).

## A-75 (GD-08) Unarmed bombs detonate on terrain; siege shells hurt ships; 02 s4.3 patched

**Decision.** (1) **A GROUND contact always detonates**, armed or not (CB6 as built). 02 s4.3 rule 2's "touches after arming" governs ship contact; terrain cannot be passed, and a dud would make the deck bomb run (02 s8, "a deck bomb run under 150 m") a no-op from under `arm_s` x fall speed, i.e. below ~15 m AGL, for no gameplay gain. Rule 3 gains "(a bomb that reaches the ground detonates whether or not it is armed)". (2) **Siege-shell blast damages ships**: 02 s4.3 gains rule 10: a siege shell deals its weapon damage (120) to every enemy entity within `blast_radius_m` (12 m), ships included, structures by footprint edge within `blast_radius_structure_m`; a direct hit is the same damage once. Without it the Crawler's shells would pass through a Dart. (3) `DEATH` cause stays `DEATH_CAUSE_DEBUG` until the cause enumeration task (GD-20's elimination work names causes; no new task).

## A-76 (TA-37) Sites do not sense; unpowered structures do; the sensor count

**Decision (02 owner question, settled here).** A structure with `F_BUILDING` set **does not sense** (a site is a footprint, not a mast; it also closes the "place a site to scout" exploit, and `Build` B4 already requires a *finished* friendly sensor for NOT_VISIBLE). An **unpowered** finished structure **senses normally**: power gates towers, production and shields (02 s5.4, GD-13), sensors are passive, and a brown-out that blinds a base punishes twice. Code: the `SensorGroups.gather` filter and a brute-force clause in `VisionTestKit` (TA-56; V1 gains the clause). **Sensor count:** 03 s4.2 row 11's "~70 sensors/tick" assumed sensors on ships only; every structure has a def `sensor_radius`, so S-SIM-1 scale is ~400 sensors per pass. The row note is corrected; the budget does not move: TA-37 measured p95 0.62-0.85 ms at 5 Hz and 0.84-0.85 ms at 10 Hz on the dev box, inside 1.1 ms.
