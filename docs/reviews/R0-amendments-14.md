## A-104 A wreck's `link` is the EntityId of the ship towing it; the `tether_target` side table is not built

**Evidence.**

1. 03 s3.1 row 31 already marks `link` as used for wrecks (W column `x`) while naming no wreck meaning; the only wreck-side state C3-17 asks for (which Hauler holds it) is exactly what the PR stores there. `EntityStore` clears `link` to 0 on free (`entity_store.gd:291`), and 0 is "none" for pads too, so the sentinel is the existing one.
2. 03 s3.2's `tether_target` row ("per Hauler: towed wreck ids and attach state") holds nothing `link[wreck]` plus F_TETHERED (bit7, both ends, 03 s3.1 row 4) does not: the per-Hauler list is the set of live wrecks whose `link` is the Hauler (<= 2, `towed_count`), the attach slot of a wreck is its rank in ascending wreck-slot order among them (deterministic, derivable, so GD-37 can give the second wreck a second anchor offset without storing one), and the follow dynamics of 03 s5.7 (critically damped spring) live in the wreck's own `pos` and, when GD-37 needs it, `vel` (row 9's W column flips "-" to `x`; every array is already sized for all 1,536 slots and serialized, so that is a doc edit, not a layout change).
3. 03 s12.2 rule 1 (03:1212) and ADR-01: sim state in packed arrays, no per-entity objects. A `RefCounted` side table per Hauler is the pattern the rules discourage when an SoA field is free. R0 B.11 A-55 is the precedent for ratifying an as-built deviation from a design-time plan when the measured code is right.
4. S4: `test_salvage_state.gd` shows save / restore / continue byte-exact mid-lifetime and mid-tow with `FORMAT` 11 unchanged. A side table would add a section and a FORMAT bump that collides with GD-10's (PR #102) for no information.

**Decision.** **Option (a), ratified.** For a `K_WRECK` slot `link[w]` is the EntityId of the ship towing it while F_TETHERED is set on `w`, and 0 otherwise; a ship's `link` keeps its pad meaning on every kind (03 s3.1 row 31 as amended: "wreck: EntityId of the towing ship (GD-19, A-104)"). A ship carries F_TETHERED exactly while at least one live wreck links to it (`Salvage` refreshes it; W7). The per-Hauler tow list and a wreck's attach slot are derived (ascending wreck slot among the wrecks linked to the ship); no `tether_target` side table exists: the 03 s3.2 row, 03 s5.7, 03 s15 "Data owned" and `sim/MODULE.md`'s Data owned sentence are reworded; C3-17's "03 side table gains `tether_target`" is superseded by this row (trailing pointer). **FORMAT:** GD-19 bumps nothing; GD-10 takes 12 at merge; the rule for every later bump is that FORMAT numbers are taken in merge order (a PR whose bump is overtaken rebases and renumbers in its `FORMAT` comment line, no other change). GD-37 adds no saved state under this ruling (the wreck's `vel` is already saved) and so bumps nothing either. **Landing while towing:** a ship that lands (DOCKED, 03 s6.4 writes `link = pad`) drops its tows first (`Salvage.drop`, the wrecks stay where they are, no event beyond the dirty bit), so `link` on the ship end never carries two meanings; GD-37 acceptance append. **Not accepted:** option (b), a `tether_target` table with a FORMAT bump (duplicate information, a RefCounted per Hauler, a collision with GD-10); a wreck-side second field for the attach slot (derivable).

## A-105 Hook reach and delivery reach are required `economy.json` fields, 33 m each

**Evidence.** The PR derives reach = `tether_len_m + tether_drop_m` (25 + 8 = 33 m) and delivery = Refinery `radius` + reach. Neither 02 s13, 03 s5.7 nor B.1 has a field; ADR-09 (01:528) and A-99 (B.18, the GD-10 dome radius: "the derivation as the rule" rejected) decide the pattern: a number that decides whether a Hauler hooks or delivers is balance and must be tunable in data, and 03:1239 forbids the literal. R0 C2-01 puts salvage / wreck constants in `economy.json`. The 33 m anchor is sound: 05 s6.5 TOW has the Hauler "descend to the wreck at 30 m AGL, hover, attach (sim)", so a Hauler hovering straight above a wreck at the brain's height is inside reach with the tether geometry as margin.

**Decision.** `economy.json` gains two **required** keys: **`salvage_hook_m` 33** (a ship with a free tow slot hooks a free wreck whose centre is within this distance of the ship's centre) and **`salvage_deliver_m` 33** (a towed wreck is delivered when its towing ship's centre is within the Refinery's `radius` + this distance; the Refinery = a finished, living structure of the ship's team whose def has `docks > 0`, W8 as written). `economy.schema.json` adds both to `properties` and `required` as `{number, minimum 1, maximum 500}` with a `$comment` citing this row; the file-level `_doc` gains "02 s13 hook / delivery reach (salvage_hook_m 33, salvage_deliver_m 33; R0 B.20 A-105: the tether geometry 25 + 8 m, 05 s6.5 hovers at 30 m AGL)"; the canonical fixture `tools/tests/fixtures/content/canonical/godot/content/defs/economy.json` gains the same keys. `Salvage.reach_m()` returns `salvage_hook_m`; delivery reads `salvage_deliver_m`; the `tether_len_m + tether_drop_m` sum disappears from `sim/salvage/`. 02 s8.1's globals table and s13 list both. Values equal today so no test tick moves. **Not accepted:** the derivation as the rule (A-99); a single field for both (the brain hovers to hook but hover-releases at the Refinery, and the two may need to diverge); a `flight_common` home (the tether geometry is kinematics, the reach is economy). **OWNER:** the two required fields (default applied); `salvage_deliver_m` 33 vs a looser value such as 50 (default 33, the measured tests).

## A-106 `SimEvent.DeathCause` opens now with 0 DEBUG, 1 EXPIRED; GD-20 appends

**Evidence.** B.12 A-75: "`DEATH` cause stays `DEATH_CAUSE_DEBUG` until GD-20 names causes" was written when nothing but `DEBUG_SET` killed; GD-19's expiry is the first sim death with a cause the HUD and analytics must tell apart from a kill (a vanished wreck is not a kill; 06 alert mapping, 04 s3.6 row 1 `cause u8`). The PR's value is right but its home is wrong: frozen ordinals live in `sim/MODULE.md` "Enumerations" and B.3 (C2-03), never in a subsystem file, and `command_applier.gd:9` already declares `DEATH_CAUSE_DEBUG = 0` in a second lane-local home.

**Decision.** B.3 gains **`SimEvent.DeathCause`** (`sim/sim_event.gd`): **0 DEBUG** (`DEBUG_SET` / test kills), **1 EXPIRED** (a wreck freed at `wreck_lifetime_s`). Append-only, frozen ordinals; GD-20 appends its causes from 2 (combat, self-destruct, terrain, whatever 02 s12.1 needs) in `sim/MODULE.md` and B.3 in its own PR, never redefining 0 or 1. `Salvage.CAUSE_EXPIRED` and `CommandApplier.DEATH_CAUSE_DEBUG` either become aliases of the enum or are replaced by it (lane choice); `test_enums.gd` (S14) covers the new enum. 04 s3.6 is unchanged (`cause u8`). A-75's "until GD-20 names causes" is superseded for the two ordinals above by this row (trailing pointer on A-75 is not needed: B.12 rows are read with B.20 appended). **Not accepted:** EXPIRED reported as DEBUG (loses the only information the event carries); the enum in `sim/salvage/` (C2-03).

## A-107 The step-9 order for one dying entity is WRECK_SPAWNED (per pod, in pod order), RELEASED(reason=DEATH) if possessed, DEATH

**Evidence.** 05 C15 (05:190): "if POSSESSED, release first; clear control fields; `RELEASED(reason=DEATH)`, `DEATH`". 04 s5.4 (04:667): "Combat kills the possessed entity at tick T; wreck spawned; control state cleared", in that order, and the client "camera holds on wreck 1.5 s" (04:669, 01 s3.1.7): the client can target the wreck at once only if the wreck's id precedes the DEATH that triggers DEAD_HOLD. 04:668 lists `DEATH ... ; RELEASED(reason=DEATH)`, which contradicts C15 and is a doc error (R0 "Authority": the register and 05's table win; 04 is fixed here). The review judged the order a non-break (no contract text ordered events inside step 9 beyond C15); the three edited tests keep RELEASED before DEATH.

**Decision.** **Ratified as contract.** In step 9, for each dying ship, ground unit or finished structure: `WRECK_SPAWNED` once per wreck or pod in pod order (none for a site, a wreck or a def with no value, W1), then `RELEASED(reason=DEATH)` if it was POSSESSED (C15), then `DEATH(entity, killer, cause)`; the slot is freed after step 9 (deferred free, 03 s4.1 note 6). Expiry (A-106 EXPIRED) emits only `DEATH`, in step 10, W4. 03 s4.1 note 7, 04 s5.4 and 05 C15 carry the sentence; `sim/salvage/MODULE.md` W3 stays as written. **Not accepted:** loosening W3 (two valid orders cost every consumer a reorder buffer for nothing).

## A-108 GD-19's boundary: four follow-ups, three of them tasks

**Decision.** (1) **Path weight 255 under a resting wreck (03 s6.1, 03:772)** is **GD-39** (sim, Sonnet, 0.5 d, after GD-19 and TA-50): `Pathing.set_weight(cell, 255)` when a wreck comes to rest, the baked weight restored (re-read from the baked map, not stored, so no FORMAT bump) when it is hooked, delivered or expires; a towed wreck blocks nothing (03 s6.1). (2) **A possessed Hauler's hook** is **GD-40** (sim, Sonnet, 0.5 d, after GD-19 and AI-10): the **DOCK** button (bit5), pressed while the ship has a free tow slot and a free wreck is within `salvage_hook_m`, hooks it instead of starting auto-dock; delivery stays automatic (W8), so no release control is needed; no new `PilotInput` bit (bit7 stays reserved; 06 s4.3's touch-button budget is full). 02 s13 carries the sentence `[planned: GD-40]`. **OWNER:** DOCK reuse (default) vs a new bit7 HOOK. (3) **`SimView.wreck_ore(id: int) -> float`** is **GD-41** (sim, Sonnet, 0.25 d, after GD-38, whose A-73 extraction makes room in `local_sim_view.gd`): the remaining Ore of a live wreck, 0.0 for anything else, -1.0 when the view has no data (`NetSimView` until a codec task carries it; `needs net:` Open item, the GD-38 pattern); TEST-02 clause and mutant. AI-15 depends on it. (4) **ORDER_DONE for HAUL / TOW:** no task; `Salvage` emits none, and by B.11 A-61 the Hauler brain (AI-15) calls `ControlOrders.complete_head` on `SALVAGE_DELIVERED` for its own id and `fail_head(INVALID_TARGET)` when the target wreck dies first (DEATH with cause EXPIRED or a hook by another ship); acceptance append.
