## A-97 What a CI unit test may assert about time on a shared runner: option (a)

**Evidence.**

1. The docs already decide this. 01 ADR-11 (01:561): perf results are gated "nightly on one pinned self-hosted runner of the production host SKU ... GitHub-hosted jobs assert correctness only, plus a same-job base-vs-head A/B at 25 % (R0 C1-11)". 03 s4.4 (03:596): "Absolute assertions ... run **only on the pinned self-hosted runner of the production SKU** (TA-42)". 03 s12.1 (03:1212): "absolute gates on the pinned production-SKU runner only". 05 s11.1 (05:973): the Perf layer's gate is "p95 assertions only on the pinned self-hosted runner". R0 C1-11 and the `ci.yml` header (line 2) repeat it. The `row x CI_FACTOR` asserts in `godot/test/unit/**` are absolute perf gates that happen to live in the unit layer; nothing in 01, 03 or 05 grants the unit layer an exemption. A-62 says the rows are measured on the pinned runner and that "a dev-box over-budget measurement never changes a row, an acceptance or `sim_budget_profile`"; a hosted-runner measurement is a dev-box measurement with a worse scheduler.
2. 10 s5.6 (10:489-495): "Only the soak, A/B perf, export-download and golden jobs are allowed to be flaky; a flaky unit/sim/net test is a bug ... quarantine is not allowed". A unit test whose verdict depends on which runner class GitHub draws is flaky by construction; option (c) ("keep absolute asserts and accept reruns") is forbidden by 10 s5.6 before any evidence is weighed, and each rerun costs the 15-minute pipeline (10 s7.4).
3. The host scale under-corrects and cannot be fixed by a better kernel (option (b)). AI-40's kernel (`_ref_step`: packed reads, `Vector3` algebra, `atan2`, one call per step) moved 1.6x between the two AI-13 runners while the brain workload moved ~2x; the ratio is not a constant of the host because the two runner classes differ in cache size and memory latency, not only in clock, and the brain's cost is dominated by `PackedVector3Array` reads over a 258-ship store that does not fit the kernel's 64-entry working set. A kernel that matched the workload would be the workload (the thing under review), and a per-test "ratio to the base commit in the same job" is exactly the A/B job that already exists (`ab_perf.py`, 7 interleaved rounds, +25 % p95). Normalisation stays as a diagnostic print; it is no longer an input to a verdict.
4. What catches a regression without a clock: the deterministic work counters AI-13 already asserts (A-96 (4): choice share, separation refresh share, <= 1 `pull_up_loss` per shaped think, 1 picture build per team per epoch, `pull_up_loss` calls per act tick while sinking == 1 / `pull_up_check_ticks`), plus the same-job A/B on code that the perf scenario exercises. The A/B scenario today drives `OrbitHook` (`perf_tick_world.gd:66-73`), a synthetic hook, so `sim_ai` think / act is **not** covered by the A/B; A-98 fixes that.

**Decision.**

1. **Option (a). On a GitHub-hosted runner a test under `godot/test/unit/**`, `godot/test/sim/**` or `godot/test/net/**` never fails on wall-clock time.** Every timing bound derived from a budget row (03 s4.2, 05 s10, 04 s4; any constant of the form `row x factor` with factor <= 3, `CI_FACTOR`, `x2 for CI`) is **report-only** on hosted runners: the test computes the figure as today, prints one line `PERF_REPORT name=<suite>.<case> us=<raw> bound_us=<bound> host=<scale or 1.00> pinned=<0|1> cite=<row>` and asserts the bound **only when the environment variable `PLANEWAR_PINNED_RUNNER` equals `1`**. TA-42 sets that variable in every job on the pinned runner; `ci.yml` never sets it; a developer may set it locally to see the asserts fire. The bounds themselves do not move (A-62, A-96 (3): the author never raises them); they become the pinned runner's gates on the day TA-42 lands, with no further ruling.
2. **Deterministic work counters are the hard assertions on hosted runners, and every perf test that goes report-only must carry at least one.** A counter bounds the work the timing used to bound: calls per think (probes, `ids_near`, `visible_to`), picture builds per epoch, refresh and choice shares, integration steps per plan, slots touched per act batch, `pull_up_loss` calls per act tick. A counter is exact or a tight band stated from the design (A-84 "every second think" = 0.50), never a measured-and-rounded figure. A perf PR that cannot name a counter for a path says so in its perf note and the reviewer decides whether the A/B scenario covers the path (A-98).
3. **Runaway guards are the one exception that may stay hard everywhere.** A bound at **>= 10x** the figure recorded in the test's own comment (dev box or CI, either) is a correctness check on algorithmic blow-up (an unbounded loop, an O(n^2) walk), not a budget, and a 2.3x host cannot trip it. Its comment must say `runaway guard` and give the measured figure; it may not cite a budget row as its source. Anything under 10x is a budget bound and follows (1). Today's set, classified by this rule for TEST-03: `test_ballistics.gd` `RELEASE_BUDGET_US` 160 / `PLAN_BUDGET_US` 240 ("doubled for CI", ~2x) -> report-only, with the step count hard; `test_flight_controller.gd:289-290` 100 us vs `track_velocity` ~3.2 us -> runaway guard; `test_overlays_perf.gd` 200 / 2000 us vs `Overlays.run` 17.2 us -> runaway guard; `test_landing_controller.gd:373-375`, `test_flight_controller_lift.gd:388,394`, `test_landing_pilot.gd:175`, `test_sc_terrain_flight.gd:118`, `test_terrain.gd`, `test_content_db.gd`, `test_ai_driver_perf.gd` `GUARD_US` 1500 -> whichever the recorded figure gives; `test_target_chooser.gd` `THINK_ROW_US` -> report-only. **OWNER:** the 10x line; default applied.
4. **One helper, one lint, one sweep: TEST-03.** `godot/test/perf_gate.gd` (`class_name PerfGate`, test-side kit beside `WorldTestKit`): `static func pinned() -> bool` (reads `PLANEWAR_PINNED_RUNNER`), `static func check(name: String, us: float, bound_us: float, cite: String, host: float = 1.0) -> bool` (prints the `PERF_REPORT` line, returns `true` when not pinned, `us < bound_us` when pinned); tests write `assert_bool(PerfGate.check(...)).override_failure_message(...).is_true()`. `tools/check_perf_gates.py` fails CI when a file under `godot/test/unit|sim|net/**` calls `Time.get_ticks_usec()` / `get_ticks_msec()` and neither references `PerfGate` nor carries the file-level comment `## timing: runaway guards only (R0 B.17 A-97)`; the reviewer checks the classification (10 s3.5 item 3). TEST-03 sweeps every file listed in (3). Until TEST-03 lands, a lane may inline the same four lines (`_gate()` reading the variable) in its own test; TEST-03 migrates them.
5. **Not accepted:** (b) as a gate (a workload-matched kernel is the workload; an in-job ratio to base is the A/B job); (c) (10 s5.6); raising `MAX_HOST` or `CI_FACTOR` (A-62: no row moves on a hosted figure; and no clamp makes two runner classes equal); quarantining or skipping the perf tests on CI (they still run and print: the `PERF_REPORT` lines are the hosted record that TA-32's `perf_report.py` may collect); moving the AI perf tests to `godot/test/perf/` only (the unit-layer tests are the per-call cost breakdown that turns "AI is slow" into a one-line task, 03 s4.4; they stay and print).
6. **Why this is not a weakened invariant (10 s4.1 "Change" row).** No budget row, acceptance figure or `sim_budget_profile` value changes; A-96's constants (`ENGAGED_MIX` 0.25, `ACT_ENGAGE_CEILING_US` 18, `row x CI_FACTOR`) stand as written and become hard on the pinned runner. The hosted runner loses an assertion it was never granted (01:561) and gains a mechanical record plus hard counters. 10 s4.1 calls a weakened invariant a Change; this is a Change in the sense that six lanes' tests move, so it is ruled here and recorded, with the owner approving.

## A-98 The same-job A/B does not cover `sim_ai` think / act today; TEST-04 adds the scenario

**Evidence.** `ab_perf.py` compares `PERF_TICK` p95 of `test/perf/perf_tick.tscn` at the A/B scale (24 ships, 8 ground, 16 structures, 60 projectiles; `perf_tick.gd:5-6`) with the `ai_assist` row driven by `OrbitHook` (`perf_tick_world.gd:66-73`): a scripted hook that fires and orbits, no brain, no `AiDriver`. A brain regression (a think that doubles, an act that allocates) is invisible to the gate; the fingerprint mechanism (`PERF_FINGERPRINT`, `HARNESS_VERSION` 3) already handles a base tree whose harness differs by skipping with a notice. AI-30's `test/perf/ai_tick` (Standard and Lite at 1,200 entities) is the pinned-runner benchmark and depends on every brain plus TA-22; it is not the hosted A/B.

**Decision.**

1. **TEST-04** (test+ci, Sonnet, 1.0 d, M3, `depends_on` AI-13, TA-03): `perf_tick.gd --ai` runs the real `AiDriver` with the Dart brain over the A/B-scale world (two teams, 48 AI Darts, the A-96 engaged mix approximated by placing one Dart in four within `fire_range` of an enemy at the start, the rest on PATROL; one `Vision` pass before the warm-up; `rules.json` think period), prints its own `PERF_FINGERPRINT ... scenario=ai` and `PERF_TICK` line; `HARNESS_VERSION` 3 -> 4; `ab_perf.py --scenario ai` passes the flag through; `ci.yml` `ab-perf` gains a second A/B step for the `ai` scenario at the same +25 % p95 threshold and a base-vs-base noise print, with rounds and ticks chosen so the job stays inside its 25-minute timeout (measured in the PR: the two scenarios' wall time per round). The default (no `--ai`) scenario and its fingerprint are unchanged so the existing A/B keeps its history. When the base tree predates TEST-04 the `ai` step skips with the existing notice; it gates from the first PR after TEST-04 merges.
2. The A/B row is the hosted-runner regression gate for `sim_ai` from then on: a brain PR's perf note cites the `ai` A/B delta beside its `PERF_REPORT` lines (03 s12.1 "a perf PR states before/after p95"). The pinned runner's AI gates stay AI-30's and 05 s11.3's.
3. **Not accepted:** replacing the default scenario by the AI one (the default's 7-round history and noise figure are S-CI-1's; the sim rows must stay measurable without AI); an A/B inside `test_dart_perf.gd` itself (a unit test cannot check out `base`; the A/B lives in the job).
