## A-92 (review Q1) PULL_UP exit: TTI >= `safety_clear_tti_s` **and** no drop-free climb need left, after `pull_up_min_hold_s`

**Evidence.** 05 s6.2's PULL_UP row (05:575) and A-89 say "exit TTI >= 4 s" (R0 B.15, 05:474 "until TTI >= 4 s"). The brain in PR #87 (`DartBrain._think`, the `m == Mode.PULL_UP` branch) exits only when `st.tti >= safety_clear_tti_s`, `st.lift <= 0` (the signed A-69 need over every probe sample, `ProbeResult.climb_need_mps` capped at `lift_max_frac x u`) and the mode has held `pull_up_min_hold_s` (0.5 s, the `safety_min_hold_s` value). The author's measurement: with the TTI-only exit the SC-10 rille leg on cradle flew into a crater wall; TTI is the **ballistic** first-contact time (A-69 keeps it ballistic on purpose), so a ship that has arrested its sink at best climb has TTI = INF while the wall further on still asks for more radial speed than `track_velocity` under the mode's `v_cmd` would deliver. With the extra condition `test_sc10_rille_low_flight_dart_brain` holds the trench 100 % <= 120 m AGL with no contact, `test_sc09_terrain_ridge_ingress_dart_brain` clears by 31 / 24 m, `test_sc11_release_terrain_imminent_on_cradle` pulls up at +0 ticks and ends with TTI >= 4 s, and 0 of 50 / 28 / 7 / 15 / 14 / 41 recoverability checks were unrecoverable (A-88 (3)). The overlay path (`Overlays.run_safety`, 05 s2.4) was not changed by the PR and passed SC-11 with its own TTI >= 4 s / 0.5 s / 3.0 s exit.

**Decision.**

1. **05 s5.3 and s6.2 amended; A-89's "exit TTI >= 4 s unchanged" is extended, not reversed.** The Dart brain's PULL_UP mode (and every brain's PULL_UP mode from AI-14 on) ends on the first think at which all three hold: (a) `AiState.tti >= safety_clear_tti_s` (4.0 s; ballistic probe, A-69), (b) the mode has held at least `guidance.pull_up_min_hold_s` (0.5 s), (c) the drop-free climb need over every probe sample is **<= 0** (`ProbeResult.climb_need_mps <= 0`: the current radial speed clears every sample by `h_req` without lift). On exit the brain resumes `prev_mode`. The exit is checked at think (3 Hz slice), never at act; the trigger side of A-89 (the 1.0 s re-sample OR the `pull_up_loss` budget at act every 3rd tick; think-time TTI < `safety_pull_up_tti_s`) is unchanged.
2. **The SAFETY overlay keeps its 05 s2.4 exit** (TTI >= 4.0 s and >= 0.5 s elapsed, or 3.0 s max). It is the released-ship hand-off, bounded on purpose (C9 / C12 / C16 / C18 return control to the standing order within 3 s); SC-11 passes on cradle with it; `Overlays` does not read `climb_need_mps`. Not accepted: adding (c) to the overlay. It would re-open AI-08's SC-11 numbers and the 3.0 s bound for a case no scenario failed.
3. **No maximum hold on the brain's PULL_UP in v1 (OWNER).** At best climb, `climb_need_mps` is non-increasing once the sink is arrested (the ship gains radial speed and altitude against fixed samples), so (c) clears when the wall is cleared; a Dart that cannot out-climb terrain at best climb is dead under any rule. A cap that fires before (c) is exactly the SC-10 failure. **Measurement first:** AI-13 reports the longest PULL_UP hold (ticks) seen in SC-09 / SC-10 / SC-11 in its PR body; if PM-01 sees holds that exceed `safety_max_hold_s` x 2 (6 s) the cap becomes a data key by amendment. **OWNER:** no cap (default) or a `guidance.pull_up_max_hold_s` cap; default applied.
4. **Why this is not a weakened invariant (10 s4.1 "Change" row).** The exit is strictly later than A-89's, so every clearance A-89 guarantees still holds; AS3 / FC5 (`sim/steer/MODULE.md`) are unchanged; no consuming lane reads the exit (`net` never sees `AiState`; the HUD sees the tag flip later). It is a 05 behaviour sentence AI-13's acceptance already owns (A-69 / A-89 appends), so it is decided here and recorded, not opened as a `contract/` branch.

## A-93 (review Q2) ENGAGE standoff and ram break-off; the `guidance` / `intercept` / `attack_run` blocks

**Evidence.** 05 s6.2 ENGAGE (05:569) commands `v_cmd` toward the lead point `L` at the target's speed + 15 m/s and leaves ENGAGE only on target death, HP drop (EVADE) or overshoot (EXTEND). 01 s3.1.3: ramming kills both ships. In PR #87's first SC-28 runs 6 of the first 8 "kills" were mutual rams (the Dart chased `L` into a Bomber flying at 1/3 of its speed). The PR adds two `intercept` keys: `standoff_m` 200 (inside it the speed target is the target's speed **minus** `engage_speed_margin_mps`, so the Dart hangs behind instead of closing through) and `break_ttc_s` 2.0 (when the target is visible, closing, and the gap `dist - r_t - r_s` is below `closing_speed x break_ttc_s`, the brain breaks off to EXTEND with a 90 degree turn to the side away from the target when the target is ahead). With both, `test_sc28_dart_intercepts_bomber` kills the Bomber 10 / 10 over seeds 0-9 (21-45 s, >= 8 required), Bomber first 10 / 10. The same PR carries three new `ap_dart` blocks (all values in `godot/test/sim/ai/ai13_autopilots.json`): `guidance` (8 keys: `kp_alt` 0.5, `vz_max_mps` 60, `waypoint_radius_m` 150, `pull_up_check_ticks` 3, `pull_up_sample_s` 1.0, `pull_up_min_hold_s` 0.5, `launch_tilt_deg` 45, `deck_speed_mps` 160), `intercept` (12 keys: `boost_close_m` 600, `lost_s` 3, `engage_extra_m` 100, `engage_speed_margin_mps` 15, `overshoot_m` 150, `extend_s` 2, `choice_period_thinks` 3, `patrol_points` 6, `patrol_switch_m` 250, `hp_window_s` 1.0, `standoff_m` 200, `break_ttc_s` 2.0) and `attack_run` (12 keys: `ip_dist_m` 2500, `ip_arrive_m` 300, `band_low_agl_m` 250, `band_high_agl_m` 600, `continue_deg` 30, `egress_turn_deg` 120, `egress_s` 6, `abort_hp01` 0.5, `max_passes` 2, `predict_dt_ticks` 2, `predict_max_steps` 120, `dive_release_frac` 0.5), plus `gun.aoa_comp_max_deg` 20 and `evade.heading_change_deg` 60. Nine of the `intercept` values and eight of the `attack_run` values are 05 s6.2 / s6.3 inline literals moved to data (ADR-09: every sim-affecting constant lives in JSON); the rest are AI-13 anchors the SC-01 / SC-09 / SC-10 / SC-28 / SC-29 runs passed with.

**Decision.**

1. **05 s6.2 ENGAGE row appended** (the Behaviour and Transitions cells; nothing removed): speed = the target's speed + `engage_speed_margin_mps` (15) beyond `standoff_m` (200) from the target, the target's speed - the margin inside it, never below the margin itself; **break-off:** target visible, closing, and the gap `dist - r_target - r_self` under `closing_speed x break_ttc_s` (2.0 s) -> EXTEND (ramming kills both, 01 s3.1.3). EXTEND's heading is "away from the target; when the target is ahead, a 90 degree break to the side away from it", then the existing `extend_s` timer -> INTERCEPT. 05 s6.2's "+ 15 m/s", "600 m", "3 s", "+ 100", "150 m", "2 s", "60 degree" literals are now the keys named above; the prose keeps the numbers as the v1.0 anchors.
2. **`autopilots.json` (R0 B.1) gains the `guidance`, `intercept` and `attack_run` blocks and the keys `gun.aoa_comp_max_deg`, `evade.heading_change_deg`: required on `ap_dart`, optional elsewhere, every key required when the block is present (A-86 pattern).** AI-14 decides which blocks Lancer / Bomber / Scout carry (`attack_run` is the obvious one for Lancer and Bomber; it is their contract question, not this ruling's). `rtb.ammo` is already in 05 s4.4. Schema ranges (`autopilots.schema.json`, AI-19): `standoff_m` [50, `gun.fire_range_m`) as a range [50, 600]; `break_ttc_s` (0, 5]; `engage_speed_margin_mps` (0, 100]; `deck_speed_mps` [60, 400]; `pull_up_check_ticks` integer [1, 10]; `pull_up_min_hold_s` (0, 3]; `aoa_comp_max_deg` [0, 45]; `heading_change_deg` [0, 180]; `choice_period_thinks` integer [1, 10]; `max_passes` integer [1, 5]; `abort_hp01` (0, 1); `dive_release_frac` (0, 1]; other keys > 0. **OWNER:** the required set (`ap_dart` only) and the two anchors 200 m / 2.0 s; default applied. S-FLIGHT-1 may retune within the ranges; a retune that changes SC-28's kill count is a PM re-baseline, not a pass or fail.
3. **Not accepted:** a brain-internal constant for either number (03 s12.2 float rule; AI-13 already has them in the fixture) or a `rules.json` home (the standoff is a Dart tactic, not a sim law; `order_rules.json` is for order validity).
4. **`deck_speed_mps` 160** stays data (SC-09 itself names 160 m/s; 05 is silent on MOVE speed; the review's item 4 is right that no amendment is needed). The think-time PULL_UP trigger, the signed A-69 need, the sink limit, the AoA compensation and the LAUNCH speed gate are inside the brain contract as the review records.

## A-94 (review Q3) `AiTag.Tag`: one append-only vocabulary for the replicated `ai_tag` u8

**Evidence.** 05 s6.1 (05:560): every brain writes its mode as a tag through `CommandSinkBase.set_ai_tag(id, tag)` into `ai_tag` u8 (03 s3.2 field 34, "opaque AI display tag"; replicated in the tier A/B flags for the own team, C2-05 / NET-39) "so the HUD can show RTB, INTERCEPT, LANDING on any unit". 03 s19 row 05 (03:1779) gives 05 / `sim_ai` the ownership of "`ai_tag` semantics"; R0 B.4 says `sim_ai` "may write `ai_tag`". PR #87's `DartBrain.Mode { NONE, LAUNCH, PATROL, INTERCEPT, ENGAGE, EXTEND, EVADE, BOMB, RETURN, DOCKED, PULL_UP, MOVE, HOLD, GUARD, ESCORT, LOITER }` is the first writer; `DartBrain.Mode` is lane-internal, so once AI-14 adds the Lancer / Bomber / Scout brains the same u8 would mean a different word per class and the HUD would need the class to decode it. `ui` may not depend on `sim_ai` (R0 B.4; `tools/deps.json`), so the HUD cannot read a `sim_ai` enum; it reads `SimView.ai_tag(id) -> int`.

**Decision.**

1. **One enumeration `AiTag.Tag`, owned by `sim_ai`, holder `godot/src/sim_ai/ai_tag.gd` (`class_name AiTag`, enum holder in the `AlertKind` form), ordinals frozen in R0 B.3 and in a new "Enumerations (append-only; ordinals frozen; R0 B.3)" block of `sim_ai/MODULE.md` in the bullet format `sim/MODULE.md` uses (03 amendment 1: growth by `MODULE.md` append, never by ADR).** Every brain writes only `AiTag.Tag` values through `set_ai_tag`; `AiState.mode` carries the same ordinal; the sim stays opaque to it (03:433 unchanged). Ordinals **0-15 are `DartBrain.Mode` of PR #87 verbatim** (NONE, LAUNCH, PATROL, INTERCEPT, ENGAGE, EXTEND, EVADE, BOMB, RETURN, DOCKED, PULL_UP, MOVE, HOLD, GUARD, ESCORT, LOITER) so no S4 bytes of the branch change. **Reserved now for the other 05 s6 brains, so AI-14 / AI-16 / AI-17 / AI-18 append nothing that collides:** 16 FLEE (Scout, Harvester), 17 SEARCH (Scout expanding search), 18 FERRY_PICK, 19 LOAD, 20 FERRY_DROP, 21 TOW, 22 CAPTURE (Hauler, s6.5), 23 PICK_FIELD, 24 TO_FIELD, 25 MINE, 26 TO_REFINERY, 27 QUEUE, 28 UNLOAD (Harvester, s6.6), 29 SIEGE (Crawler on its firing spot, s6.7), 30 RELOCATE (Crawler), 31 TRACK (tower slewing to a target, s6.8), 32 OFFLINE (tower under 50 % power), 33 IDLE (tower / structure with nothing to do). A class that needs a word not here appends it at the end in its own PR ("Contract impact: append"). PR #87 is not merged, so `DartBrain.Mode` **may be replaced** by `AiTag.Tag` without a delete; if the author keeps `DartBrain.Mode` as a lane-internal alias, `test_dart_brain.gd` asserts every member equal to its `AiTag.Tag` namesake (the A-50 `Protocol.PlayerKind` precedent).
2. **The HUD strings are content, not code:** `godot/content/ui/ai_tags.json` (06 owner, the `alerts.json` / `pings.json` pattern of B.3) maps every ordinal to a string id and a short label; `tools/validate_content.py` checks that every `AiTag.Tag` ordinal has an entry (count parity with the `sim_ai/MODULE.md` bullet, the way `test_protocol.gd` parses the `sim/MODULE.md` block). **UX-43** (ui+content, Haiku, 0.25 d) writes the file, its schema and the check. `ui` never names `AiTag` (no `deps.json` change); it reads `SimView.ai_tag(id)` and the JSON.
3. **Not accepted:** a `sim/ai_tag.gd` holder (would make the sim interpret a field 03 declares opaque and would need a new `ui` named sim type: a 10 s4.1 Change for no gain); per-class tag spaces (the HUD would need the class to decode a u8; 05 s6.1 wants one word per unit); a string tag (the u8 is replicated per entity in the A/B flags, 04).

**Decision.**

PR #87 reorders its history so the contract test (`test_climb_need_is_the_drop_free_requirement_over_every_sample`) and the `MODULE.md` line precede the code commit (10 s3.5), fixes the "ST5" comment to ST3, and flags "Contract impact: append (sim/steer `ProbeResult.climb_need_mps`)". **PR #87 rebases on `main` before merge and keeps AI-41's `test_flight_controller_equivalence.gd` line** in `sim/steer/MODULE.md` "Test entry points"; a merge that drops it is a delete and is refused by the reviewer.
2. **TA-63** (sim, Sonnet, 0.5 d, `depends_on` TA-37, M3): `SimView.visible_enemy_ships(team: int, out: PackedInt32Array) -> int` (B.5 append, `[planned: TA-63]`): fills `out` (caller-owned, grown once, no allocation per call) with the EntityIds of live **ships** of another team (or neutral) that `team` saw at its last vision pass, from the `InterestGrid` team list (O(visible), not O(slots)); returns the count; `visible_to(team, id)` is true for every id returned (contract test); identical before and after `deserialize` + `rebuild_lists` (S4); a `perf` test records us per call at the AI-40 host scale beside `TeamPicture`'s 222 us. `visible_ids` stays as is (not a delete; its `MODULE.md` comment "live list, rebuilt per vision pass" is corrected to "allocates; walks every live slot" by TA-63). `sim_ai` adopts it in a follow-up inside AI-13's lane (the `TeamPicture` build becomes one call per team per pass); AI-13 itself does **not** depend on TA-63: the review's levers (rebuild per vision pass, `alive` check in `near`, cache invalidation on `bind_rng` / deserialize) are inside the brain contract.
3. **Not granted here: a perf guard factor above `row x CI_FACTOR` for the engaged think / act.** A-62 and A-84 say no row moves and no acceptance widens on a dev-box or CI-runner figure; the review's levers (picture per vision pass, cached RTB pad, choice period 6, separation every 2nd think, one `pull_up_loss` in `_shape`, cached aim lead outside `fire_range`) are untried.
