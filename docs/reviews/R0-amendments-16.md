## A-111 (CQ-2, BLOCKED) `net` may name `TeamStateView`, `PlayerStateView` and `OrderSpec`

**Evidence.**

1. **The contradiction is between two binding texts, both ours.** R0 B.5 (`sim/MODULE.md:134-145`) gives `SimView` the signatures `order_head(id) -> OrderSpec`, `pending_order(id) -> OrderSpec`, `team_state(team) -> TeamStateView`, `player_state(slot) -> PlayerStateView`. 04 s5.6 and 01 s9.3 require `NetSimView` to "implement the full `SimView` interface of R0 B.5" and pass the shared contract test. B.4 / `tools/deps.json` let `net` name `SimView` but not those three return types, so `check_deps.py` D1 (`tools/depscheck/rules_src.py:35`, match by class name) fails any override. The PR correctly stopped (CLAUDE.md "If the acceptance cannot be met inside the contract, stop").
2. **The precedent.** A-27 (B.9, 01 amendment-log row 46) appended `SimEvent` and `CommandResult` to the same list for the same reason (a `net` signature returned a `sim` type the list lacked). 01:990 says the module list and layering direction do not change, "only named exceptions were added"; this is one more named exception, in the same direction (`net` reads `sim`, which B.4 already allows for nine types).
3. **The alternatives break something binding.** Moving the three value types to `core` makes `core` know team economy, orders and players (B.4: `core` owns `PLANET_RADIUS` and Godot built-ins; B.8 A-8 put the views in `sim/` on purpose). An adapter above `net` (in `app` or `ui`) means `NetSimView` does not implement `SimView`, contradicting 04 s5.6, 01 s9.3 and TEST-02's whole premise (one contract test, two implementations). Neither is a third position; the named list is the mechanism 01 built for exactly this.
4. **`ui` already names `OrderSpec`** (B.4 `ui` row), so no new type crosses a layer boundary for the first time; `TeamStateView` / `PlayerStateView` are `RefCounted` value views with no methods that mutate the sim (B.8 A-8).

**Decision (OWNER, default applied as A-27 was).** Append **`TeamStateView`, `PlayerStateView`, `OrderSpec`** to `net`'s named `sim` types in `tools/deps.json`, R0 B.4's `net` row, 01 s9.2's `net` row and the 03 s12.4 D1 row (all four in this PR; `check_deps.py` passes with no code change). Nothing else is named: `PlayerTable`, `OrderQueue`, `TeamState` stay `sim`-internal; `ai_tag` stays an opaque `int` (A-94). **Who implements what:** the four accessors are **NET-39**'s ("NetSimView accessors of 04 s3.7 with the unknown bit"; 04 s3.7 sources `order_head` / `pending_order` from `TEAM_DETAIL` orders, `player_state` from `TEAM_DETAIL` players + `PLAYER_STATUS` (A-8), `team_state` from `TEAM_STATE` plus `members` from the player table, which only `TEAM_DETAIL` carries). **PR #118 changes no code for this:** the factory's exempt entries `team_state`, `player_state` (and `order_head`, `pending_order`, already under the TEAM_DETAIL reason) stay with the reason rewritten from "BLOCKED (CQ-2)" to "NET-39, R0 B.22 A-111", and the `net/client/MODULE.md` open item is closed the same way. The `BLOCKED` label clears because the contract question is answered and the work has an owner.

**Not accepted:** a `net`-side `NetTeamState` / `NetOrder` twin (two types for one value, and `NetSimView` would still not implement `SimView`); naming the whole `sim` module for `net` (B.4 keeps `net` off `sim` internals so the codec cannot read `EntityStore` arrays directly).

## A-112 (CQ-1) Replicated projectile entities have a roster index: the roster gains a projectile block

**Evidence.**

1. 04 s3.6 bullet 2: "Bombs, rockets, siege shells, Supply Canisters (SL-5) and wrecks **are entities** ... and are replicated in tiers like ships. A bomb or siege shell is a 19-byte FULL record once; ... POS_SMALL ...". A FULL / DELTA record is addressed by roster index (04 s3.1, s3.4), so a replicated projectile needs one.
2. 04 s3.1 and A-54 size the roster at 1,536 = `EntityStore` slots 0-1,535 ("because wrecks are replicated entities, 3.6"). The same sentence's reasoning applies to projectile entities and was not carried through when A-54 widened the roster for wrecks. `ProjectileStore` slots are 4,096-6,143 (03 s3.1 table, `EntityId.PROJECTILE_SLOT_MIN / _END`), outside the roster; `Roster.CAPACITY` 1,536 (`net/roster.gd:6`) and every array sized from it (`BaselineFrame`, `Interest`, `InterestClient`, byte cache) cannot hold them.
3. 04 s3.7 maps `projectiles_near` to "client-spawned `PROJECTILE_BATCH` projectiles + replicated projectile entities" and `incoming_rockets` to the pilot block; 04 s4.5's canonical scene counts "60 rockets/bombs/siege shells (replicated)" and tier A holds "6 rockets/bombs". The design always intended these as roster entities; only the index space was never written down.
4. **Constraints on the mapping.** NET-49's byte cache writes FULL and C-BLIP bodies once per tick indexed by roster index and appends them to every client's packet, so the roster index must be a **client-independent function of the sim slot** (a per-client binding table would defeat the cache). 04 s3.1 already says roster indices "reuse the sim slot number only inside `KEYFRAME` / `ENTITY_META`" and the gap encoding escapes to a `u16` absolute index, so any index < 65,536 is encodable. `InterestClient._KEY_SHIFT` 11 assumes `CAPACITY <= 2048` (a lane constant, not contract).

**Decision.** The roster index space is **`index = slot` for `EntityStore` slots 0-1,535 and `index = 1,536 + (slot - EntityId.PROJECTILE_SLOT_MIN)` for `ProjectileStore` slots 4,096-6,143**: a contiguous 2,048-entry projectile block, **`Roster.CAPACITY` 3,584**, no per-client state, no byte moves (`ENTITY_META` / `KEYFRAME` keep carrying the sim slot as `u16`; the gap rule of 04 s3.1 is unchanged; the mean gap of ~6 is unchanged for ships and the one jump into the block costs one 3-byte escape per section). Only projectile entities of kinds **ROCKET, BOMB, SIEGE_SHELL, CANISTER** enter a roster (slugs, flak shells and rail slugs never do, 04 s3.6 bullet 1; `ProjectileStore.kind`); their `ENTITY_META` carries `def_id` = the `ProjectileDef` id, `owner` and `team` of the shooter. **Interest (04 s4.1):** a projectile entity is in a client's visible set `V` when its owner is on the client's team or when its shooter or its target is in `V` (projectiles have no sensors and no `visible_mask`; the shooter / target are already tiered), and it is tiered by its own position with the A / B / C rules; it is `ROSTER_REMOVE`d on death with no 30 s ghost (it is gone). `ENTITY_META` traffic on the canonical scene: ~12 spawns/s (60 live, ~5 s mean life) x 9 B plus the removes, ~0.2 KB/s inside the 04 s4.6 slack; the s4.6 row gains a note. Dead reckoning is unchanged: bombs / siege shells take the gravity branch of 04 s3.4 through `gravity_def`, rockets the linear one. **`NetSimView`:** `alive`, `pos`, `vel`, `basis`, `def_id`, `owner`, `team`, `radius`, `def_kind`, `read_poses`, `ids_in_cell`, `ids_near` and `projectiles_near` resolve projectile ids through the block; `projectiles_near` returns the replicated entities only (client-spawned slugs are presentation and have no `EntityId`; 04 s3.7 "approximate by design" stands). **Code = NET-58** (net, Opus, 1.0 d, M3, after NET-17; `Roster.CAPACITY` and the sized arrays, `Roster.index_of_slot` / `slot_of_index`, `RosterCodec` range checks, `Interest` projectile candidates and META emission, `SnapshotCodec.prepare_tick` over `ProjectileStore` entities of the four kinds, `NetSimView` resolution, `_KEY_SHIFT` 12, the TEST-02 rocket clauses asserted in `test_net_sim_view.gd`). The factory's seven CQ-1 exempts stay in PR #118 with the reason "NET-58, R0 B.22 A-112"; the wreck-invisibility part of those clauses (`visible_to(0, wreck)` is false in the scene) is a legitimate 04 s4.1 exemption and stays after NET-58.

**Not accepted:** a bounded binding block (for example 512 entries, keeping `CAPACITY` 2,048) with a server-side free list: it adds per-match allocation state, a "not replicated above the cap" degrade path no doc describes, and a second id mapping to keep bit-identical on both ends; a `PROJECTILE_ENTITY` message outside the snapshot: contradicts 04 s3.6 ("replicated in tiers like ships") and would need its own delta / baseline machinery.

## A-113 (CQ-3) The TEST-02 scene conforms to B.3 and the contract takes a per-accessor tolerance from the factory

**Evidence.** `simview_scene.gd:16` writes `CONTROL = 5` into `control_state`, whose B.3 domain is 0 AUTO, 1 ORDERED, 2 POSSESSED and whose wire form is 2 bits (04 s3.3 flags bits 0-1): a `LocalSimView` reads 5 back, a `NetSimView` cannot, and 5 is not a legal sim state. `simview_contract.gd:9` compares every float to `EPS = 1e-4`; `flip_cooldown01` travels as a `u8` (04 s3.3 pilot block: 0.5 -> 128/255 = 0.50196, error 0.00196). The scene already sets `possessor = 0` on `a` and scripts the state after the last `step()`, so POSSESSED is the consistent value and changes nothing else the clauses test. The mutant corrupts floats by +0.25 and ints by +1 (`simview_mutant.gd:295-300`), so a tolerance of one wire quantum keeps every mutant failing.

**Decision.** **TEST-5** (test lane, Haiku, 0.25 d, M3, lands **before** PR #118 merges): (1) `SimViewScene.CONTROL` becomes **2** (POSSESSED; `a` has `possessor` 0), the clause text unchanged; (2) `SimViewFactory` gains **`func tolerance(accessor: StringName) -> float`** returning `SimViewContract.EPS` by default, and `SimViewContract._near(a, b, accessor)` compares with `absf(a - b) <= factory.tolerance(accessor)`; the LocalSimView factory keeps 1e-4 everywhere; a replicated factory may return **one wire quantum of the field's 04 s3.3 encoding** (`1.0 / 255` for `hp01`, `flip_cooldown01`, `supply01`, `shield01`, `progress01`-class fields; `fuel01` = 0.1 s / `fuel_s`) and nothing coarser; the mutant test asserts every mutant still fails under the NetSimView tolerances. **PR #118** then rebases, drops `control_state` and `flip_cooldown01` from `exempt()` and overrides `tolerance` (04 s3.3 "Error" column is the only number source). The clause bodies keep their meaning: same values, same accessors, same scene; only the legal state and the comparison width change. 04 s5.6 gains one sentence recording the tolerance rule.

## A-114 (Q5) A split wreck's radius is the def default with `unknown` set

**Evidence.** `salvage.gd:217` sets a split wreck's `radius` to the hull radius / n; `WRECK_SPAWNED` (04 s3.6 row 19: `wreck u16, from_def u16, ore u16`) and `ENTITY_META` carry no `n` or radius, and 04 s3.7 has no `radius` row (it is def-derived everywhere else). The client uses a wreck's radius for presentation scale only (collision is server-side, 03 s6.1; `projectiles_near` and `ids_near` take explicit radii).

**Decision.** `NetSimView.radius(wreck)` returns the **def radius** (`from_def` via `ENTITY_META` `def_id`, the same value `LocalSimView` gives an unsplit wreck) **with the entity's `unknown` bit set**; this is 04 s5.6's rule for a field the client does not receive, so no exemption reason beyond "04 s5.6 / A-114" is needed and no code changes in PR #118. If presentation wants split wrecks drawn smaller (GD-19 visuals), the path is an **appended trailing byte `n_split u8` on `WRECK_SPAWNED`** (8 -> 9 B, a payload append under 04 s3.6's own rule, `PROTOCOL_VERSION` bump) filed as a net task by the presentation task that needs it; not created now.

## A-115 (Q6 and the perf note) Every 03 budget row is p95; dev-box and hosted-CI numbers never re-price a row

**Evidence.** 03 s4.4: "Budget is **p95 per tick** (R0 B.7)"; 01 s8.4 (01:638): "tick p95 <= 25 ms, p99 <= 33 ms"; 03 s12.1 (03:1214, 1221): perf rows are `{p50, p95, p99}`, a perf PR states p95, absolute gates run on the pinned runner only; A-62 (B.11) and A-97 (B.17): a dev-box or hosted-runner measurement never changes a row, an acceptance or a profile, and a hosted CI test never fails on wall-clock time. 03 s10.2 lists the client per-frame rows without naming a percentile. Measured (PR #118): `ClientSession.tick` p50 0.49-0.60 ms, p95 1.09-1.30 ms dev box; hosted CI p50 0.92 / p95 1.97 ms; the p95 ticks are the 1-in-15 tier-C ticks (04 s4.1 schedule `(tick + k) % 15 == 0` lands a client's whole C set on one tick), dominated by `SnapshotDecoder`; prediction (NET-18) is not in the number yet. `NetSimView.read_poses` over 940 entities 3.4 ms p50 vs the "entity sync 2.4" row, which is presentation's (TA-52 measured 2.9-3.4 ms for `LocalSimView` on the same row; TA-55's `PoseStager` splits the read across two frames; the pinned-runner gate is TA-42).

**Decision.** (1) **The 03 s10.2 rows are p95**, like every other 03 budget row; 03 s10.2 gains the words. (2) **No row is re-priced** (A-62 / A-97: pinned-runner data at PM-01 only); the PR's numbers are recorded as a dev-box note in 03 s10.2 and in `net/client/MODULE.md` (the PR has it), and `PerfGate` stays report-only off the pinned runner (A-97). (3) **Levers, named, not scheduled:** L1 **stagger tier C by roster index** (C entity `e` of client `k` is sent when `(tick + k + index(e)) % 15 == 0` instead of all of `C` on one tick: the same bytes, the same 2 Hz per entity, the decode and encode cost spread evenly over 15 ticks; a 04 s4.1 schedule edit, server-side only, no client change, no wire change; NET-08's `Interest`, Sonnet, 0.5 d) is the first lever if the pinned runner shows the row over 1.0 ms p95 once NET-18 adds prediction; L2 `NetSimView.read_poses` on tick frames over `PoseStager`'s half set is already the TA-55 shape, and the remaining lever there is presentation's "per-view transform writes" (TA-55 note). **NET-18**'s perf note re-measures the whole row (decode + `NetSimView` + prediction) on the canonical scene and states p50 / p95; **TA-42**'s first pinned run records `ClientSession.tick` beside the server rows. No new task.
